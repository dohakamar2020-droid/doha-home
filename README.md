# بيتي منظم — Bayti Monazam

تطبيق ويب عربي (RTL) لتنظيم يوم البيت: مهام يومية وأسبوعية، جدول تنظيف الغرف، عادات يومية، ونسخ احتياطي محلي.
كل البيانات تُحفظ في متصفح المستخدمة فقط — بدون سيرفر، بدون قاعدة بيانات، وبدون أي طلبات خارجية.

> **App name:** بيتي منظم (Bayti Monazam) · **Version:** 1.0.0

## نظرة سريعة

- **7 صفحات:** `/welcome` (إعداد أول مرة)، `/` (الرئيسية)، `/today`، `/week`، `/cleaning`، `/habits`، `/settings`.
- **RTL بالكامل** بخط Cairo، تصميم هادي بألوان: sage `#719B83`، cream `#FAF7F2`، soft pink `#F5E5E8`، نص `#28332D`.
- **Mobile-first**: شريط تنقل سفلي على الموبايل، سايدبار على الديسكتوب، من 320px وفوق.
- **بدون مزامنة:** البيانات محلية، مع تصدير/استيراد JSON.
- **اختبارات:** 101 اختبار وحدة/مكوّن بـ Vitest + RTL، و34 حالة Playwright E2E موزّعة على موبايل وديسكتوب.

## الصفحات والميزات

### `/welcome` — الإعداد الأول
- ويزارد 4 خطوات: الاسم (اختياري) + وقت الصحيان والنوم → بداية الأسبوع → قالب البداية → مراجعة.
- قوالب البداية: **يوم هادي وخفيف**، **يوم بيت متوازن**، **يوم مليان ومشغول** — كلها تُنشئ مهام وعادات ومهام تنظيف قابلة للتعديل والحذف.
- لو تم الإعداد قبل كده: إعادة زيارة `/welcome` **لا تعيد إنشاء** أو تمسح أي بيانات (تُحدَّث الإعدادات فقط).

### `/` — الرئيسية
- ترحيب حسب الوقت + الاسم، تاريخ اليوم بالعربي.
- نسبة إنجاز اليوم، عدد المهام المكتملة والمتبقية، أقرب مهمة قادمة، معاينة مهام اليوم.
- تنظيف مستحق النهاردة (بإمكانك تعليمه)، عادات النهاردة، زر مهمة سريعة، وتنقل سريع لكل الأقسام.
- حالة فاضية ودّية لو مفيش مهام.

### `/today` — جدول اليوم
- تنقل بين الأيام (أزرار + اختيار تاريخ + زر «النهاردة»).
- مهام مرتبة بالوقت في قسم، والمهام من غير وقت في قسم تاني.
- إضافة/تعديل/حذف (بتأكيد)/إكمال/إلغاء إكمال/إعادة جدولة بتاريخ، مع الأولوية والفئة والملاحظات والمدة والتكرار.
- فلترة بالحالة والفئة والأولوية + شريط تقدّم اليوم.

### `/week` — المخطّط الأسبوعي
- تقويم 7 أيام حسب بداية الأسبوع المختارة، مع عدد مهام كل يوم ونسبة إنجازه.
- تنقل بين الأسابيع، اختيار يوم، إضافة/تعديل/إكمال/نقل مهام لليوم المختار.
- المهام المتكررة تظهر تلقائيًا في الأيام المناسبة.

### `/cleaning` — تنظيف البيت
- 6 غرف افتراضية: المطبخ، الحمام، أوضة النوم، الصالة، الغسيل، البيت عمومًا — قابلة للإضافة وإعادة التسمية والحذف.
- لكل غرفة مهام تنظيف بمواعيد **يومية/أسبوعية/شهرية**، وملاحظات.
- لوحات: **متأخر**، **مستحق النهاردة**، **الجاي**، مع آخر تاريخ إكمال لكل مهمة.
- تعليم الإكمال بتاريخ الميعاد المستحق (لو متأخر) أو بتاريخ اليوم.

### `/habits` — العادات
- إنشاء/تعديل/حذف عادة، اختيار أيام الأسبوع الفعّالة.
- تسجيل الإنجاز لأي يوم مختار، مصفوفة أسبوعية (`HabitTracker`) وتقدّم أسبوعي لكل عادة.
- **السلسلة (streak)** لا تُحسب على الأيام غير المجدولة ولا تنكسر بها، واليوم الحالي غير المكتمل لا يكسر السلسلة قبل انتهائه.

### `/settings` — الإعدادات والبيانات
- تعديل الاسم، وقت الصحيان، وقت النوم، بداية الأسبوع، وإظهار/إخفاء الأقسام من التنقل.
- تصدير JSON (تنزيل ملف)، استيراد JSON مع **تحقق Zod** و**معاينة الملخص قبل الاستبدال** و**تأكيد صريح**.
- شرح واضح أن البيانات محلية وأن مسح بيانات المتصفح قد يضيّعها.
- تصفير التطبيق بعد تأكيد، وعرض رقم الإصدار.

## نموذج البيانات والتخزين

المخططات في `src/lib/schemas.ts` (Zod)، والأنواع في `src/types/domain.ts` مشتقة منها مباشرة (`z.infer`)، فمافيش فرصة لاختلاف بين التحقق والأنواع.

```ts
type AppData = {
  version: 1;
  settings: UserSettings;
  tasks: Task[];
  taskCompletions: TaskCompletion[];      // سجل إكمال منفصل: { taskId, date, completedAt }
  rooms: Room[];
  cleaningTasks: CleaningTask[];
  cleaningCompletions: CleaningCompletion[];
  habits: Habit[];
  habitCompletions: HabitCompletion[];
};
```

- **معرّفات UUID** عبر `crypto.randomUUID()` مع بديل آمن.
- **التواريخ** دائمًا `YYYY-MM-DD` محلية (بدون وقت)، وسجلات الإكمال مرتبطة بتاريخ اليوم المحلي.
- **مفتاح التخزين:** `bayti-monazam:data` — كائن واحد بإصدار `version: 1`.
- **الترحيل:** `migrateRawData` يحوّل الإصدار 0 (بدون حقل `version`) إلى الشكل الحالي، ويرفض بأمان أي نسخة أحدث، وأي بيانات تالفة/غير صالحة تُعرض كخطأ مع خيار البدء من جديد.
- **التحديثات غير قابلة للتغيير (immutable):** كل عمليات `src/lib/operations.ts` ترجع `AppData` جديدة.
- **SSR آمن:** لا وصول لـ `window` أو `localStorage` أثناء البناء. أول render يعرض حالة تحميل، ثم يتم التحميل في `useEffect` — فلا hydration mismatch.
- **الحفظ التلقائي** بعد كل تغيير، مع معالجة: التخزين غير متاح، البيانات التالفة، `QuotaExceededError` (رسالة واضحة بدون فقدان البيانات الحالية من الذاكرة).
- **تزامن بين التابات** عبر حدث `storage`.

## قواعد التكرار والتقويم

- **مرة واحدة:** تاريخ واحد فقط.
- **يومي:** من `startDate` (شامل) حتى `endDate` إن وُجد.
- **أسبوعي:** أيام الأسبوع المختارة داخل المدى.
- **شهري:** يوم الشهر المختار. **لو الشهر أقصر من اليوم المطلوب (مثلاً 31 في فبراير أو أبريل) تُنفَّذ المهمة في آخر يوم في الشهر.** هذا السلوك موثّق هنا وفي واجهة النموذج، ويُحسب عبر `Math.min(dayOfMonth, daysInMonth)`.
- لا يتم **توليد نسخ مهام** إطلاقًا؛ التكرار يُحسب عند الطلب لكل تاريخ (`occursOn`). لذلك لا يوجد نسخ غير محدودة ولا نمو غير مسيطر عليه.
- **إكمال نسخة لا يكمل النسخ المستقبلية:** سجل الإكمال مرتبط `(taskId, date)`، والتحقق من الإكمال يمر بالتاريخ.
- **تعديل مهمة** لا يحذف سجلات الإكمال التاريخية (السجلات منفصلة تمامًا عن تعريف المهمة).
- **إعادة الجدولة:** لمهمة مرة واحدة تُغيّر تاريخها؛ للمهام المتكررة تُنقل بداية السلسلة (وللشهري يتغيّر يوم الشهر) بدون مسح السجلات القديمة، والواجهة توضّح ذلك.
- **لا حذف تلقائي للمهام غير المكتملة عند منتصف الليل، ولا إكمال تلقائي.**
- الحسابات تستخدم UTC داخليًا على مكوّنات التاريخ فقط، بعيدًا عن مشاكل التوقيت الصيفي، مع حدود الشهور والسنوات الكبيسة.

## النسخ الاحتياطي والاستيراد

- صيغة الملف:

```json
{
  "app": "bayti-monazam",
  "backupVersion": 1,
  "exportedAt": "2026-10-21T10:00:00.000Z",
  "data": { "version": 1, "settings": {}, "tasks": [], "…": "…" }
}
```

- التصدير ينزّل `bayti-monazam-backup-YYYY-MM-DD.json`.
- الاستيراد يتحقق من: `app`، `backupVersion` (≤ 1)، وكل بيانات `data` عبر Zod، **قبل** أي تعديل.
- بعد التحقق تُعرض معاينة (اسم، تاريخ التصدير، عدد المهام/السجلات/الغرف/العادات)، وبعدها زر «استبدال البيانات».
- الملفات غير الصالحة تُرفض برسالة عربية واضحة ولا تلمس البيانات الحالية.

## الوصولية والأداء

- HTML دلالي، `lang="ar" dir="rtl"`، رابط «تخطي إلى المحتوى».
- كل الحقول ليها `label` مرتبط، والأخطاء مرتبطة بـ `aria-describedby` و`aria-invalid`.
- حوارات بـ `role="dialog"`، `aria-modal`، حصر التركيز داخل الحوار، إغلاق بـ Escape، وإرجاع التركيز بعد الإغلاق.
- أهداف لمس ≥ 44px في الأزرار الأساسية، حالات `aria-pressed` / `aria-checked` / `aria-current`، ورسائل تنبيه `aria-live` (Toasts).
- تباين ألوان يستهدف WCAG AA (نص داكن `#28332D` على cream/white، وأزرار sage-500 بنص أبيض).
- `prefers-reduced-motion` يوقف الأنيميشن والانتقالات.
- كل الصفحات static، بدون طلبات API، والخط يُقدَّم محليًا من الحزمة.
- تصميم من 320px، بدون تمرير أفقي (جدول العادات داخل منطقة تمرير محتواة).

## الاختبارات

```bash
npm test          # 101 اختبار (Vitest + jsdom + Testing Library)
npm run test:e2e  # Playwright: 17 حالة × مشروعين (mobile + desktop)
```

**تغطية اختبارات الوحدة (`tests/unit`):**
- تنسيق التواريخ، بدايات الأسابيع وحدود الشهور/السنوات الكبيسة، الأوقات والمدد.
- التكرار اليومي/الأسبوعي/الشهري (بما فيها 31 في شهر قصير و29 فبراير)، والتنظيف والعادات.
- حالة الإكمال وحسابات التقدّم، وسلاسل العادات (عدم معاقبة الأيام غير المجدولة).
- ترحيل البيانات، صلاحية النسخ الاحتياطي، معالجة التخزين التالف/الممتلئ.
- اختبارات مكوّنات: إنشاء مهمة، تعديلها، إكمالها، أخطاء النموذج، حوارات التأكيد، الحفظ بعد إعادة التحميل.
- اختبارات دخان لكل صفحة (ترتيب/عرض/تفاعل) داخل `StoreProvider`.

**Playwright (`tests/e2e`):** الإعداد الأول، إضافة/إكمال مهمة، الثبات بعد إعادة التحميل، التنقل بين الأيام، التكرار الأسبوعي، إكمال تنظيف، العادات، تصدير/استيراد النسخة الاحتياطية (بما فيها ملف غير صالح)، والتنقل على الموبايل + فحص عدم وجود تمرير أفقي.

> **شفافية:** آخر تشغيل فعلي في هذه البيئة كان لـ `npm test` (نجحت 101 اختبارًا) و`npm run build` و`npm run lint` و`npm run typecheck`.
> اختبارات Playwright لم تُشغَّل هنا لأن تنزيل متصفحات Playwright محجوب في بيئة التنفيذ؛ الملفات مكتوبة ومتحقَّق من تحميلها واكتشافها (`npx playwright test --list` → 34 اختبار)، وتُشغَّل عبر `npx playwright install --with-deps chromium && npm run test:e2e` محليًا أو في GitHub Actions.

## النشر على Vercel

1. ارفعي المستودع على GitHub.
2. في Vercel: **Add New → Project → Import** المستودع.
3. Framework Preset: **Next.js** (يُكتشف تلقائيًا).
4. Build Command: `npm run build` — Output: `.next` — Install: `npm ci` (Vercel يختار `npm ci` تلقائيًا عند وجود `package-lock.json`).
5. Node.js Version: **22.x** (Project Settings → General).
6. لا متغيرات بيئة مطلوبة. Deploy.

بعد النشر: كل الصفحات static، والبيانات محلية لكل متصفح. لا حاجة لقاعدة بيانات أو جلسات.

## CI على GitHub Actions

`.github/workflows/ci.yml` يعمل على `push` و`pull_request`:

- **quality:** `actions/setup-node@v4` مع Node 22 وذاكرة npm → `npm ci` → `npm run lint` → `npm run typecheck` → `npm test` → `npm run build`.
- **e2e:** يعتمد على quality → `npx playwright install --with-deps chromium` → `npm run test:e2e` (webServer يبني ويشغّل التطبيق)، ويرفع تقرير Playwright عند الفشل.

## الخصوصية

- لا يتم جمع أو إرسال أي بيانات مهام أو أسماء أو سجلات إلى أي خادم.
- لا يوجد تحليلات أو تتبع أو كوكيز إعلانية.
- البيانات في `localStorage` تحت مفتاح واحد، ويمكن حذفها من الإعدادات أو تصديرها.

## الحدود المعروفة

- **البيانات محلية فقط:** لا مزامنة بين الأجهزة. مسح بيانات المتصفح أو استخدام وضع التصفح الخاص قد يضيع البيانات؛ لذلك يوجد تصدير/استيراد.
- **لا وضع Offline:** لا يوجد Service Worker أو استراتيجية أصول offline (والتطبيق لا يدّعي ذلك).
- لا نظام استثناءات لنسخة واحدة من مهمة متكررة (مثلاً «تخطّي يوم واحد بس»). إعادة الجدولة تنقل بداية السلسلة، والواجهة تشرح ذلك.
- تنبيهات المتصفح (Push/Notifications) غير مدعومة؛ التطبيق يعرض المهام المستحقة داخل الواجهة فقط.
- إخفاء قسم من الإعدادات يخفيه من قوائم التنقل فقط؛ يمكن الوصول إليه بالرابط المباشر.
